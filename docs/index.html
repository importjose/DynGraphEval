DynGraphEval

A framework for evaluating what temporal graph models actually learn

tgbl-wiki benchmark  ·  TGN, TGN+FixedEnc, TGAT, TGAT+FixedEnc, GraphMixer, EdgeBank

1. The Task

A temporal graph is a sequence of timestamped edges $(u, v, t)$ recording interactions between nodes over time. In the tgbl-wiki dataset, nodes are Wikipedia editors and articles; each edge represents an edit event.

The task is temporal link prediction: given all interactions up to time $t$, predict which edge $(u, v)$ occurs next. This is harder than static link prediction — a static model only needs to learn which pairs of nodes tend to connect. A temporal model must reason about when a link occurs, not just whether it could occur.

2. Standard MRR

The accepted evaluation metric for temporal link prediction is Mean Reciprocal Rank (MRR).

How evaluation works

For each test edge $(u, v, t)$, the model is given a multiple-choice question: here is source node $u$ at time $t$ — which of these 1000 destinations does it visit next? One candidate is the true destination $v$; the other 999 are negatives $\mathcal{N}$ (destinations that did not occur at this moment). The model scores all 1000 and ranks them.

  • Rank 1 — the true destination scored above all 999 negatives. Score: $1/1 = 1.0$.
  • Rank 2 — one negative scored higher. Score: $1/2 = 0.5$.
  • Rank 10 — nine negatives scored higher. Score: $1/10 = 0.1$.
  • Rank 1000 — the model placed the true destination last. Score: $\approx 0$.

MRR is the average of these per-edge reciprocal ranks across all test edges:

$$\text{MRR} = \frac{1}{|E_\text{test}|} \sum_{(u,v,t)\,\in\, E_\text{test}} \frac{1}{\text{rank}(v \mid u,\, t,\, \mathcal{N})}$$

An MRR of 1.0 means the model ranked the true destination first every time. Random guessing among 1000 candidates gives MRR $\approx 0.001$. On tgbl-wiki, state-of-the-art temporal models score in the range 0.55–0.60.

The TGB negatives

The TGB benchmark uses a hist_rnd negative sampling strategy: 50% of the 999 negatives are drawn from destinations the source has visited historically (but is not visiting right now), and 50% are random nodes. The historical half is harder — the model must distinguish "link that has existed" from "link occurring right now." The random half is easy — random nodes have little reason to be visited. This mix is fixed for all models on the TGB leaderboard.

3. EdgeBank: a memorization baseline

Before introducing any model, consider EdgeBank — a baseline with no parameters, no training, and no temporal reasoning whatsoever. EdgeBank scores a candidate destination 1 if the (source, destination) pair has been seen before, and 0 otherwise:

$$\text{score}_\text{EdgeBank}(u,v) = \mathbf{1}\!\left[(u,v) \in E_\text{train} \cup E_\text{val}\right]$$

EdgeBank cannot reason about time, recency, or sequence — it simply memorizes which pairs have ever co-occurred. Under Standard MRR on tgbl-wiki, it scores 0.495. The best neural model (TGN+FixedEnc) scores 0.692.

EdgeBank achieves 72% of TGN+FixedEnc's Standard MRR through pure memorization. The gap between all neural models is 0.143. The gap between TGN+FixedEnc and a model with zero temporal reasoning is only 0.197.

Standard MRR is largely a memorization test. A model that cannot reason about time at all sits just below the entire leaderboard.

Why Standard MRR rewards memorization

The TGB negatives are 50% historical destinations and 50% random nodes. EdgeBank scores any historically-seen destination 1 and everything else 0. For a test edge where the true destination has been visited before, EdgeBank scores it 1 while most random negatives score 0 — it wins easily. The 50% historical negatives are harder (they also score 1), but still only half the pool.

Standard MRR cannot distinguish a model that has learned temporal patterns from one that has simply memorized which pairs have co-occurred. The negatives are not adversarial to memorization — they do not specifically test whether a model knows what comes next, only whether it recognizes links that have existed. A harder metric is needed.

4. Recency MRR

The question a temporal model should be able to answer is not "has this link existed before?" but rather "given everything that just happened, what comes next?"

To probe this directly, we replace TGB's standard negatives with recency negatives: for each test edge $(u, v, t)$, the negatives are the $K$ destinations $u$ visited most recently before time $t$ — the edges $u$ just came from. These are temporally adjacent alternatives to the true next link.

This is a harder test than Standard MRR for two reasons:

  • Recency negatives are almost always in EdgeBank's memory too — memorization cannot separate the positive from the negatives.
  • Models with a learned recency bias (e.g., a trainable time encoder) actively inflate the scores of these negatives, making the positive harder to rank.

Formal definition

Let $H_u(t)$ denote the unique destinations visited by $u$ before time $t$, ordered most-recent-first. The recency negative set for a test edge $(u, v, t)$ is:

$$\mathcal{N}_K(u,v,t) \;=\; H_u(t)_{[1:K]} \setminus \{v\}$$ $$\text{RecencyMRR}(K) \;=\; \frac{1}{|\mathcal{E}_K|} \sum_{(u,v,t)\,\in\,\mathcal{E}_K} \frac{1}{\text{rank}\!\left(v \;\middle|\; u,\, t,\, \mathcal{N}_K(u,v,t)\right)}$$ $$\text{where } \mathcal{E}_K = \{(u,v,t) \in E_\text{test} : |\mathcal{N}_K(u,v,t)| \geq 1\}$$

Edges where the source has no prior history get no negatives and are excluded. There is no random fill — a source with few historical visits simply gets fewer negatives. Rank is computed using TGB's tie-handling formula:

$$r_\text{opt} = 1 + \textstyle\sum_{i} \mathbf{1}[s^-_i > s^+] \qquad r_\text{pess} = 1 + \textstyle\sum_{i} \mathbf{1}[s^-_i \geq s^+] \qquad \text{MRR}_\text{edge} = \frac{2}{r_\text{opt} + r_\text{pess}}$$

EdgeBank under Recency MRR

Test edges split naturally into two types, which we will analyze in depth in section 6:

  • Return edges — the source has visited this destination before (in train or val).
  • Explore edges — the source has never visited this destination before.

Under Recency MRR, EdgeBank scores 0.362 — far below every neural model. For a Return edge, both the positive destination and every recency negative have been seen before, so EdgeBank scores everything 1. The tie-handling formula then produces rank $\approx K/2$, collapsing MRR toward zero for large $K$. For an Explore edge, the positive destination has never been seen (score = 0) while every recency negative has been seen (score = 1) — the positive always loses, rank = $K+1$. EdgeBank's Recency MRR of 0.362 is not zero only because many sources have sparse histories (few recency negatives → small tie pool → moderate rank). It is the ceiling for pure memorization on this metric.

The gap between EdgeBank and the worst neural model (TGAT, 0.773) is larger under Recency MRR (0.411) than the gap between the best and worst neural models under Standard MRR (0.052). Recency MRR is a much stronger discriminator of temporal reasoning.

Note: Recency MRR and Standard MRR are on different scales — the absolute values should not be compared across metrics. What matters is relative ordering within each metric.

6. Return vs Explore

The inversion exists. But why? To understand the mechanism, we label every test edge before evaluation:

$$\text{Return}(u,v) = \mathbf{1}\!\left[(u,v) \in E_\text{train} \cup E_\text{val}\right] \qquad \text{Explore}(u,v) = \mathbf{1}\!\left[(u,v) \notin E_\text{train} \cup E_\text{val}\right]$$
  • Return edges — the source has visited this destination at least once before. Predicting these requires temporal recall: recognizing that this pair is likely to reconnect.
  • Explore edges — the source has never visited this destination. Predicting these requires structural generalization: inferring that a new destination is plausible from context alone.

On tgbl-wiki there are 10,380 Return edges and 4,089 Explore edges in the test set. These are meaningfully different tasks and each model responds to them differently.

The Return/Explore gap scales with the memory bank, not the encoder

Models with a memory bank (TGN, TGN+FixedEnc) have larger gaps (0.113–0.117) than models without (TGAT, TGAT+FixedEnc, GraphMixer: 0.047–0.090). Within each architecture, switching the encoder from trainable to fixed barely changes the gap: TGN → TGN+FixedEnc (0.113 → 0.117), TGAT → TGAT+FixedEnc (0.086 → 0.090). The memory bank specializes the model toward Return edges by explicitly tracking prior visits, widening the gap by making Return MRR much higher without a corresponding Explore improvement.

EdgeBank's gap (0.108) is structural and extreme: on Return edges it scores the positive 1 (seen before) and ties with most negatives; on Explore edges it scores the positive 0 (never seen) while all recency negatives score 1. The positive cannot win.

The trainable encoder provides no benefit — in any configuration

Comparing encoder types within each architecture:

  • TGN vs TGN+FixedEnc: freezing the encoder improves every metric. Standard MRR +0.091, Recency MRR +0.015, Explore MRR +0.012.
  • TGAT vs TGAT+FixedEnc: freezing the encoder changes nothing. Recency MRR +0.001, Explore MRR −0.001 — within noise.

In neither case does the trainable encoder help. It either actively hurts (TGN) or is completely neutral (TGAT). The learnable time encoder is spending model capacity on something that contributes nothing — a fixed sinusoidal encoding captures all the temporal structure the model can use.

The Explore MRR scores for all trainable encoder models cluster tightly: TGN 0.708, TGAT 0.711, TGN+FixedEnc 0.720, TGAT+FixedEnc 0.710. GraphMixer (0.787) is the clear outlier — its advantage over TGAT+FixedEnc (0.077) cannot be explained by encoder type alone since both use fixed encoders. The MLP-Mixer architecture itself is doing something different.

TGN+FixedEnc leads on Return edges; GraphMixer is close

TGN+FixedEnc achieves the highest Return MRR (0.837), narrowly ahead of GraphMixer (0.834) and TGN (0.821). The memory bank does provide a slight advantage on Return edges once the trainable encoder's recency noise is removed. However, the advantage is small: GraphMixer, with no memory bank and a fixed encoder, is competitive within 0.003. The likely reason TGN lags: its trainable encoder inflates scores for more recent competing destinations, crowding out the true positive even when it has been visited before.

7. The K-curve

Recency MRR at a single $K$ (how many of the most recent negatives to include) summarizes performance at one depth. The K-curve computes Recency MRR at $K \in \{10, 20, 50, 100, 500, 999\}$ from a single evaluation pass.

Because recency negatives are stored ordered most-recent-first, slicing neg_scores[:k] gives the model scores for the $k$ most recent visits without re-running the model. The K-curve is a temporal reach curve: it measures at what depth a model's memory advantage stops being useful.

TGAT0.7850.7780.7740.7730.773−0.012

The curve is flat for all models

The predicted shape was different. TGN's GRU memory bank was expected to hold signal at large K; GraphMixer's 20-neighbor window was expected to drop off past K ≈ 20. Instead, all models drop only 0.012–0.014 from K=10 to K=999. The full architectural bias is expressed at K=10 already. Adding more historically-recent negatives beyond the first 10 adds competitors scored similarly to the shallower ones.

EdgeBank's curve also drops (−0.010) for a different reason: at K=10, sparse sources have smaller tie pools and thus moderately higher MRR; at K=999, tie pools grow and compress MRR further. Its flatness confirms the result is not about depth — it is about the inability to distinguish the positive from any of the negatives at all.

The K-curve's diagnostic value is deferred to the federated learning experiments. If federation fragments TGN's memory bank, the federated K-curve should begin dropping at larger K while the centralized curve stays flat — and the crossover K becomes a quantifiable measure of what partitioning costs in temporal memory.

9. Related Work

Poursafaei et al. (2022), Towards Better Evaluation for Dynamic Link Prediction, identified a related problem: random negative sampling makes evaluation trivially easy. They introduced EdgeBank and proposed two harder negative strategies:

  • Historical NS — negatives drawn from any historically-seen edge for that source.
  • Inductive NS — negatives drawn from edges never observed.

Their split is at the negative pool level: two separate evaluation runs using different pools. The key question is "does the negative pool matter?" — and yes, model rankings change significantly.

DynGraphEval is complementary. The differences:

  • Our recency negatives are not just any historical edge — they are the most recent unique visits for that source, ordered by recency. The temporal ordering is what makes them adversarial to models with recency bias.
  • Our split is at the positive edge level: every test edge is labeled Return or Explore. The question is "does the type of edge being predicted matter?" — and yes, the Return/Explore gap directly reveals the mechanism behind the Standard/Recency inversion.
  • The K-curve is entirely absent from Poursafaei et al.

Poursafaei et al. show that which edges are used as negatives changes what is measured. We show that which type of edge is being predicted also changes what is measured, and that combining both reveals architectural mechanisms that neither approach can isolate alone.

10. Interpretation

Standard MRR and Recency MRR measure opposite sides of the same bias

Trainable time encoders learn to upweight recently-visited destinations. Under Standard MRR, this is a good heuristic — the random negatives are not recent, so recent destinations rank above them correctly. Under Recency MRR, this same bias is adversarial — the negatives are recent, so the encoder inflates exactly the wrong scores. The inversion is not noise; it is a precise reflection of how each architecture processes time.

What each architectural component contributes

  • Trainable time encoder (TGN, TGAT) — provides no benefit in any configuration. TGN+FixedEnc beats TGN on every metric. TGAT+FixedEnc matches TGAT exactly. The learnable encoder is spending model capacity on something a fixed sinusoidal encoding already captures. In TGN's case it actively hurts by learning a recency bias that inflates negative scores; in TGAT's case it is simply redundant.
  • Memory bank (TGN, TGN+FixedEnc) — drives the Return/Explore gap. With encoder held fixed, TGN+FixedEnc (memory) beats TGAT+FixedEnc (no memory) by +0.037 on Return and +0.010 on Explore. The memory bank specializes the model toward Return edges by explicitly tracking prior visits, but doesn't help generalize to Explore edges.
  • GraphMixer anomaly — GraphMixer (no memory, fixed encoder) leads Recency MRR (0.821) and Explore MRR (0.787), well above TGAT+FixedEnc (0.774, 0.710) which shares the same encoder type and memory absence. The MLP-Mixer architecture itself is contributing something beyond what encoder type and memory bank explain — likely its uniform neighbor aggregation avoids the attention mechanism's tendency to focus on the most recent interactions.

The 2×2 matrix is complete

Both ablations are done. The central finding: the learnable time encoder is not needed and should be removed. A fixed sinusoidal encoder matches or exceeds it in every configuration. The memory bank provides a modest, measurable Return edge advantage once encoder noise is removed, but does not help Explore. GraphMixer's MLP-Mixer architecture remains an outlier whose advantage on Explore edges cannot be explained by the 2×2 factors alone.
