DynGraphEval

tgbl-wiki  ·  tgn · tgat · graphmixer · tpnet · fl-tgn · fedlink

A multi-dimensional evaluation framework for temporal graph link prediction models. Built on the TGB benchmark, it decomposes model performance along axes that Standard MRR cannot see — revealing what temporal graph models actually learn and where that learning breaks down under federated constraints.

The Problem with Standard MRR

Temporal graph link prediction asks: given the history of interactions up to time $t$, predict which edge $(u, v)$ will occur next. Models are evaluated using Mean Reciprocal Rank (MRR) — rank the true edge above a set of negative (non-occurring) edges and measure how high it places.

$$\text{MRR} = \frac{1}{|E_\text{test}|} \sum_{(u,v,t) \in E_\text{test}} \frac{1}{\text{rank}(v \mid u, t, \mathcal{N})}$$
where $\mathcal{N}$ is the set of negative candidates and $\text{rank}(v \mid u, t, \mathcal{N})$ is the position of $v$ when scored against $\mathcal{N}$.

TGB's standard negative sampling (hist_rnd) draws 50% of negatives from the source node's historical destinations and 50% from random nodes in the graph. This produces 999 negatives per positive edge.

The Problem
Standard MRR rewards models that learn temporal recency bias — assigning high scores to recently-visited destinations. This bias helps rank the true next edge above historical or random negatives, but it is a different skill from genuinely predicting the next event in a temporal stream. A model can score well on Standard MRR by learning a shortcut.

The Shortcut

Trainable time encoders (used by TGN and TGAT) learn that recent neighbors are more likely future destinations. This is useful: it raises scores for recent links. But the negatives in Standard MRR are not specifically recent — they're historical or random. So the bias helps discriminate the true edge from those negatives.

The problem becomes visible when negatives are temporally hard — specifically chosen to be the most recently visited unique destinations for that source. Now the same recency bias inflates the negative scores, making the true edge harder to rank. Standard MRR rewards the bias; temporally-grounded evaluation is punished by it.

Empirical Evidence
On tgbl-wiki, Standard MRR and Recency MRR produce inverted rankings: TGN (0.601) > TGAT (0.568) > GraphMixer (0.549) on Standard MRR, but GraphMixer (0.821) > TGN (0.789) > TGAT (0.773) on Recency MRR. The same learned behavior that wins on one metric loses on the other.

Evaluation Framework

DynGraphEval decomposes test performance along two axes that Standard MRR conflates:

Axis 1 — Edge Type: Return vs Explore

Every test edge $(u, v, t)$ is labeled before evaluation using the training and validation history:

$$\text{Return}(u,v) = \mathbf{1}\!\left[(u,v) \in E_\text{train} \cup E_\text{val}\right]$$ $$\text{Explore}(u,v) = \mathbf{1}\!\left[(u,v) \notin E_\text{train} \cup E_\text{val}\right]$$
  • Return edges: source $u$ has visited destination $v$ at least once before. Predicting these correctly requires temporal recall — the model must remember that this link has occurred and judge it likely to recur.
  • Explore edges: source $u$ has never visited destination $v$. Predicting these requires structural generalization — the model must infer that this new destination is plausible from graph structure or node features, without any direct memory of the pair.
Why this split matters
A memory bank (like TGN's GRU) gives a model direct signal for Return edges but no additional signal for Explore edges. A model with a strong recency bias may actually hurt on Explore edges — it scores known recent destinations highly, making it harder to rank a novel destination above them.

Axis 2 — Temporal Depth: The K-Curve

For each positive edge $(u, v, t)$, we construct recency negatives: the $K$ most recently visited unique destinations by $u$ before time $t$, in reverse-chronological order (most recent first). Formally, let $H_u(t)$ be the sorted sequence of unique destinations visited by $u$ before $t$:

$$H_u(t) = \text{unique\_reverse\_chron}\!\left(\{d : \exists\, t' < t,\, (u,d,t') \in E_\text{train}\}\right)$$ $$\mathcal{N}_K(u,v,t) = H_u(t)_{[1:K]} \setminus \{v\}$$

We evaluate once at $K = 999$ and store per-edge scores. The K-curve is then computed in post-processing by slicing the stored negative score arrays:

$$\text{RecencyMRR}(K) = \frac{1}{|\mathcal{E}_K|} \sum_{(u,v,t) \in \mathcal{E}_K} \frac{1}{\text{rank}(v \mid u, t, \mathcal{N}_K(u,v,t))}$$ \text{where } \mathcal{E}_K = \{(u,v,t) : |\mathcal{N}_K(u,v,t)| \geq 1\}

Because negatives are stored in recency order, slicing neg_scores[:k] gives the model scores for the $k$ most recent unique visits — no re-running the model needed. The resulting K-curve is a temporal reach curve: it shows at what depth a model's memory stops being useful.

MRR Computation

For a single positive edge with score $s^+$ ranked against negative scores $s^-_1, \ldots, s^-_K$ (ordered most-recent-first), we use TGB's tie-handling formula:

$$r_\text{opt} = 1 + \sum_{i=1}^{K} \mathbf{1}[s^-_i > s^+]$$ $$r_\text{pess} = 1 + \sum_{i=1}^{K} \mathbf{1}[s^-_i \geq s^+]$$ $$\text{MRR}_\text{edge} = \frac{2}{r_\text{opt} + r_\text{pess}}$$

For the K-curve at depth $k$, only $s^-_1, \ldots, s^-_{\min(k, K_i)}$ are used, where $K_i \leq 999$ is the actual number of recency negatives for edge $i$. Edges with fewer than $k$ historical visits contribute with their actual count.

Scale note
Standard MRR and Recency MRR are not on the same scale — recency negatives are harder on average for dense sources and easier for sparse ones (no random fill). What matters is the relative ranking across models, not the absolute values.

Key Findings

Finding 1 — Standard MRR and Recency MRR are inversely correlated

The model that wins on Standard MRR (TGN, 0.601) loses on Recency MRR (0.789). The model that loses on Standard MRR (GraphMixer, 0.549) wins on Recency MRR (0.821). The rankings are completely inverted. This is not noise — it is the same learned behavior (temporal recency bias) measured from two opposite sides.

Finding 2 — The Return/Explore gap reveals the mechanism

The Return/Explore gap is ordered by architectural complexity:

  • TGN (memory bank + trainable encoder): gap = 0.113
  • TGAT (no memory, trainable encoder): gap = 0.086
  • GraphMixer (no memory, fixed encoder): gap = 0.047

The trainable time encoder is the primary driver, not the memory bank. TGN and TGAT score nearly identically on Explore edges (0.708 vs 0.711) despite TGN having a full GRU memory bank. The memory bank adds only marginal additional bias on novel destinations. The trainable encoder alone creates most of the gap.

Mechanism
A trainable time encoder learns to assign high scores to recently-visited destinations. On Explore edges, every negative is a recent visit and the positive is a novel destination. The encoder's bias inflates all the negative scores and depresses the novel positive, collapsing Explore performance. GraphMixer's fixed encoder does not learn this bias and treats all neighbors uniformly — so novel destinations are not penalized.

Finding 3 — The K-curve is flat for all models

The predicted finding was that GraphMixer's 20-neighbor window would cause its K-curve to drop as K grows past 20, while TGN's GRU memory would keep its curve flat. In practice, all three models show nearly flat K-curves (drop of only 0.012–0.014 from K=10 to K=999).

This is itself a result: the temporal depth of the negatives is not the key driver. The model's architectural bias is already fully expressed at K=10. Going deeper into the negative list adds candidates that are scored similarly to the shallower ones. The mechanism is not "how many historical visits are in the negative set" but "how much the model's encoder inflates scores for any recently-visited destination."

Finding 4 — GraphMixer dominates on both Return and Explore

Unexpectedly, GraphMixer beats TGN even on Return edges (0.834 vs 0.821). The memory bank was expected to give TGN a clear advantage on Return edges (it has direct recall of seen links). Instead, TGN's recency bias hurts even here: the recency negatives may be more recently visited than the true positive (which may be a link from weeks ago), causing the model to mis-rank it. GraphMixer's uniform treatment of neighbors does not have this problem.

Relation to Prior Work

Poursafaei et al. 2022 — Towards Better Evaluation for Dynamic Link Prediction

The most closely related prior work. They identify that random negative sampling produces artificially easy evaluation — a non-parametric memorization baseline (EdgeBank, which simply stores all seen edges) outperforms sophisticated temporal models under random negatives. They propose two harder negative sampling strategies:

  • Historical NS: negatives drawn from any previously observed edge (real but not current positive)
  • Inductive NS: negatives drawn from edges never observed in training

Poursafaei et al. 2022

  • Split is at the negative pool level
  • Historical NS vs Inductive NS = two separate evaluation runs
  • Asks: "does the negative pool matter?"
  • Finding: harder negatives change model rankings
  • No temporal ordering within negatives
  • No K-curve or depth analysis
  • Centralized models only

DynGraphEval (this work)

  • Split is at the positive edge level
  • Return/Explore labels each test edge
  • Asks: "what type of prediction is being made?"
  • Negatives are specifically the most recent unique visits (temporal hardness)
  • K-curve measures temporal reach depth
  • Return/Explore × K = full diagnostic table
  • Federated learning extension (FL-TGN, FedLink)

Our Recency NS is strictly more specific than Historical NS: rather than sampling from any historical edge, we take the $K$ most recent unique destinations for that specific source, in reverse-chronological order. The temporal ordering is what enables the K-curve and makes the negatives genuinely adversarial to models with recency bias. Their work and ours are complementary:

Positioning
Poursafaei et al. show that which edges are used as negatives changes what is measured. We show that which edges are used as positives (Return vs Explore) also changes what is measured — and that the two decompositions together reveal architectural mechanisms neither can isolate alone.

TGB (Huang et al. 2023)

The Temporal Graph Benchmark provides standardized datasets, splits, and negative samplers. DynGraphEval builds on TGB's infrastructure — Standard MRR is computed using TGB's exact negatives and evaluator, making results directly leaderboard-comparable. Recency MRR is an additional pass with a custom negative set.

TGN, TGAT, GraphMixer, TPNet

The centralized model baselines evaluated here. TGN (Rossi et al. 2020) uses a GRU memory bank and trainable time encoding. TGAT (Xu et al. 2020) uses temporal attention with a trainable time encoder but no persistent memory. GraphMixer (Cong et al. 2023) uses a fixed (non-trainable) time encoder and MLP-Mixer aggregation. TPNet is the current TGB leaderboard leader and uses random projections for temporal walk aggregation.

Federated Learning Extension next

The federated models (FL-TGN and FedLink) are the dissertation's core contribution. The evaluation framework above makes precise predictions:

Model Return MRR Explore MRR K-curve shape Hypothesis
FL-TGN (4 clients, source partition) ↓ vs centralized TGN ≈ TGN Droops at large K Partitioned memory bank breaks cross-client recall; Explore unaffected since no memory helps there anyway
FedLink (static GraphSAGE) ↓↓ (no temporal memory) ↓ (no structural generalization) Flat (no temporal component) Static model cannot exploit temporal patterns at all; federation hurts uniformly

The K-curve crossover point is particularly informative for FL-TGN: if the federated model's curve drops at $K > K^*$ while the centralized model stays flat, then $K^*$ is a direct measure of how many time steps of memory federation costs. This would be a concrete, quantifiable claim about the cost of source-node partitioning on temporal graph memory.

Statistical Validation later

  • Multiple seeds (3–5 runs) — current results are seed=0 only. Return/Explore gap differences on the order of 0.02–0.03 need confidence intervals before a strong claim can be made.
  • Second dataset — replicate on tgbl-coin or tgbl-review to confirm the Standard/Recency inversion is not tgbl-wiki-specific.

Open Questions

  • Why is GraphMixer also better on Return edges? The memory bank was expected to give TGN a return advantage. The current hypothesis is that TGN's recency bias mis-ranks some Return edges where the true positive is not the most recent visit. Confirming this requires inspecting per-edge scores and the relative timestamp of the positive vs the most recent recency negative.
  • Is the flat K-curve universal? All three centralized models show a flat K-curve. If FL-TGN's curve drops at large K (fragmented memory), that would be the first non-flat curve and would validate the K-curve as a diagnostic. If FL-TGN is also flat, the K-curve measures something structural about the negative distribution rather than model architecture.
  • Can a model be designed that wins on both metrics? A model that avoids temporal recency bias in its encoder (like GraphMixer) but adds explicit memory for Return recall (like TGN) should be able to close the gap. This could be a model design contribution.
