DynGraphEval

A framework for evaluating what temporal graph models actually learn

tgbl-wiki benchmark  ·  TGN, TGAT, GraphMixer, EdgeBank

1. Background

A temporal graph is a sequence of timestamped edges $(u, v, t)$ recording interactions between nodes over time. In the tgbl-wiki dataset, nodes are Wikipedia editors and articles; each edge represents an edit event. The task is temporal link prediction: given all interactions up to time $t$, predict which edge $(u, v)$ occurs next.

This is harder than static link prediction. A static model only needs to learn the graph structure — which pairs of nodes tend to connect. A temporal model must reason about when a link occurs, not just whether it could occur. Specifically, a good temporal model should be able to predict the next event in a stream, not just recognize that a link has historically existed.

The standard evaluation metric is Mean Reciprocal Rank (MRR):

$$\text{MRR} = \frac{1}{|E_\text{test}|} \sum_{(u,v,t)\,\in\, E_\text{test}} \frac{1}{\text{rank}(v \mid u,\, t,\, \mathcal{N})}$$

For each test edge $(u, v, t)$, the model scores $v$ alongside a set of negative (non-occurring) destinations $\mathcal{N}$. The reciprocal rank of $v$ in this scored list is averaged over all test edges. The TGB benchmark generates 999 negatives per edge using a hist_rnd strategy: 50% drawn from destinations the source has visited historically, 50% random nodes.

2. The Problem with Standard MRR

Standard MRR is the accepted leaderboard metric, but it conflates two different skills: link recognition (this pair has connected before) and temporal prediction (this link is about to happen next). A model can score well on Standard MRR by learning a simple heuristic without genuinely reasoning about time.

The recency shortcut

Trainable time encoders — used by TGN and TGAT — learn to assign high scores to recently-visited destinations. This is a reasonable inductive bias: recent activity often predicts future activity. And it works well under Standard MRR, because the negatives are drawn from the source's full history or at random. Recent destinations are not over-represented in the negatives, so the recency bias helps rank the true next edge above them.

The problem surfaces when you construct negatives that are recent — specifically, the most recently visited unique destinations for that source just before the test edge. Now the same recency bias inflates the scores of those negatives, making the true next edge harder to rank. A model is essentially being punished for exactly the property that won it Standard MRR.

Standard MRR rewards temporal recency bias. A temporally-grounded evaluation penalizes it. The two metrics are measuring the same learned behavior from opposite sides.

What this means empirically

On tgbl-wiki, Standard MRR and Recency MRR (described below) produce completely inverted model rankings:

ModelStandard MRRRecency MRR
TGN (memory bank + trainable encoder)0.6010.789
TGAT (no memory, trainable encoder)0.5680.773
GraphMixer (no memory, fixed encoder)0.5490.821
EdgeBank (memorization baseline)0.4950.362

The model that wins Standard MRR loses Recency MRR, and vice versa. This is not noise — it is a direct consequence of how each model processes temporal information.

The memorization floor

EdgeBank is a non-parametric baseline that scores a candidate link 1 if the (source, destination) pair has been seen before, and 0 otherwise — no parameters, no training, no temporal reasoning. Under Standard MRR it scores 0.495, only 0.106 below TGN. A large fraction of Standard MRR is achievable by memorization alone.

Under Recency MRR, EdgeBank scores 0.362 — well below every neural model. The recency negatives are all edges the source recently visited, meaning they are all in EdgeBank's memory too. Both the positive and every negative score 1, creating a complete tie that the tie-handling formula resolves to near-random rank. EdgeBank cannot distinguish what was visited recently from what will be visited next.

The chart below shows how large a model's advantage over EdgeBank is on each metric. The Recency MRR gap is 4–8× larger than the Standard MRR gap for every model — Recency MRR amplifies differences in temporal reasoning while Standard MRR partially masks them behind memorization.

3. Related Work

Poursafaei et al. (2022), Towards Better Evaluation for Dynamic Link Prediction, identified a related problem: random negative sampling makes evaluation trivially easy. They showed that a non-parametric memorization baseline (EdgeBank — simply storing all seen edges) outperforms sophisticated temporal models when negatives are random. They proposed two harder negative sampling strategies:

  • Historical NS — negatives drawn from any edge seen in training (but not the current positive). Tests whether models can predict edge recurrence.
  • Inductive NS — negatives drawn from edges never observed. Tests generalization to new links.

Their split is at the negative pool level: two separate evaluation runs with different pools of negatives. The question they ask is "does the negative pool matter?" — and the answer is yes: model rankings change significantly.

DynGraphEval is complementary. The key differences:

  • Our recency negatives are not just any historical edge — they are the most recent unique visits for that specific source, ordered by recency. The temporal ordering is what makes them adversarial to models with recency bias.
  • Our split is at the positive edge level: we label each test edge as Return or Explore (described below), not just the negative pool.
  • The K-curve (described below) is entirely absent from Poursafaei et al.

Poursafaei et al. show that which edges are used as negatives changes what is measured. We show that which type of edge is being predicted also changes what is measured, and that combining both reveals architectural mechanisms neither approach can isolate alone.

4. The DynGraphEval Framework

We decompose test performance along two axes.

4.1 Recency MRR

For each test edge $(u, v, t)$, recency negatives are the $K$ most recently visited unique destinations by $u$ before time $t$, ordered most-recent-first. Let $H_u(t)$ denote those destinations in reverse-chronological order:

$$\mathcal{N}_K(u,v,t) \;=\; H_u(t)_{[1:K]} \setminus \{v\}$$ $$\text{RecencyMRR}(K) \;=\; \frac{1}{|\mathcal{E}_K|} \sum_{(u,v,t)\,\in\,\mathcal{E}_K} \frac{1}{\text{rank}\!\left(v \;\middle|\; u,\, t,\, \mathcal{N}_K(u,v,t)\right)}$$ $$\text{where } \mathcal{E}_K = \{(u,v,t) \in E_\text{test} : |\mathcal{N}_K(u,v,t)| \geq 1\}$$

Edges where the source has no historical visits receive no recency negatives and are excluded. There is no random fill — a source with few historical visits simply gets fewer negatives.

The question Recency MRR asks is different from Standard MRR. Standard MRR asks: "can the model rank this link above arbitrary negatives?" Recency MRR asks: "can the model rank the true next link above the links the source visited just before this moment?" This is a genuinely temporal question.

MRR is computed using TGB's exact tie-handling formula:

$$r_\text{opt} = 1 + \sum_{i} \mathbf{1}[s^-_i > s^+] \qquad r_\text{pess} = 1 + \sum_{i} \mathbf{1}[s^-_i \geq s^+] \qquad \text{MRR}_\text{edge} = \frac{2}{r_\text{opt} + r_\text{pess}}$$

Note: Recency MRR and Standard MRR are not on the same scale and should not be compared as absolute values. What matters is the relative ordering across models.

4.2 Return vs Explore split

Every test edge $(u, v, t)$ is labeled before evaluation:

$$\text{Return}(u,v) = \mathbf{1}\!\left[(u,v) \in E_\text{train} \cup E_\text{val}\right]$$ $$\text{Explore}(u,v) = \mathbf{1}\!\left[(u,v) \notin E_\text{train} \cup E_\text{val}\right]$$
  • Return edges — source $u$ has visited destination $v$ at least once before. Predicting these correctly requires temporal recall: the model must recognize that this pair has connected before and judge it likely to reconnect.
  • Explore edges — source $u$ has never visited destination $v$. Predicting these requires structural generalization: the model must infer that a destination it has never associated with this source is plausible, based on graph structure or broader context.

These are meaningfully different tasks. A memory bank (like TGN's GRU) gives direct signal for Return edges — it has literally seen this pair before. It gives no additional signal for Explore edges. The split lets us measure whether a model's advantage comes from recall or generalization.

4.3 The K-curve

Recency MRR at a single $K$ is a harder metric, but it does not explain why one model beats another. The K-curve computes Recency MRR at $K \in \{10, 20, 50, 100, 500, 999\}$ from a single evaluation pass.

Because negatives are stored ordered most-recent-first, slicing neg_scores[:k] gives the model scores for the $k$ most recent visits. No re-running the model is needed — all K values are computed in post-processing.

The K-curve is a temporal reach curve: it shows at what depth a model's memory stops being useful. The predicted shapes were:

  • TGN (GRU memory bank) — flat curve; accumulated memory retains signal at large K.
  • GraphMixer (20-neighbor window) — drops past K ≈ 20; neighbors beyond that window are not encoded.

What we actually found (discussed in the results) was different from both predictions.

The K-curve is also the key diagnostic for the planned federated learning experiments. If federation fragments the memory bank, TGN's curve should start drooping at larger K — the crossover point quantifies exactly how many time steps of memory partitioning costs.

5. Models

ModelMemoryTime encoderDescription
TGN GRU memory bank Trainable Node states updated after each interaction via GRU. Temporal attention over neighborhood.
TGAT None Trainable Multi-head temporal attention. Time encoded via a trainable sinusoidal basis. No persistent state.
GraphMixer None Fixed (non-trainable) MLP-Mixer over the most recent K neighbors. Time encoded via a fixed non-trainable function. No persistent state.
EdgeBank Seen-pair set None Non-parametric baseline. Scores 1 if (src, dst) has been seen before, 0 otherwise. No learning, no temporal reasoning.

The three neural architectures span a space of design choices. TGN has both a persistent memory bank and a trainable time encoder. TGAT has a trainable encoder but no memory. GraphMixer has neither — it treats neighbors uniformly using a fixed encoding. This progression lets us isolate which architectural component drives the results we observe.

5.1 EdgeBank as a baseline

EdgeBank is included as a memorization floor. It has no parameters and no temporal reasoning — it simply remembers which (source, destination) pairs have occurred and scores 1 for seen pairs, 0 for unseen ones. Its memory is initialized from train+val and updated rolling during test evaluation (EdgeBank∞ variant).

EdgeBank's scores under Recency MRR are not near zero, despite being unable to distinguish the positive from the negatives, because tie-handling depends on pool size. When a source has only a small training history, the tie pool is small and the resulting MRR is moderate (e.g. 5 negatives all tied → rank ≈ 3.5, MRR ≈ 0.29). The 0.362 overall Recency MRR reflects this distribution over sparse histories — it is the best a memorizaton-only model can do.

7. Interpretation

The inversion is real and explained

Standard MRR ranks TGN first and GraphMixer last. Recency MRR inverts this completely. The Return/Explore split reveals why: the gap between Return and Explore performance scales directly with how much temporal learning each architecture does.

  • TGN (memory bank + trainable encoder): gap = 0.113
  • TGAT (trainable encoder only): gap = 0.086
  • GraphMixer (fixed encoder): gap = 0.047

More temporal learning → larger Return/Explore gap → bigger Recency MRR penalty.

The trainable encoder, not the memory bank, drives Explore collapse

TGN and TGAT score almost identically on Explore edges: 0.708 vs 0.711. Despite TGN having a full GRU memory bank, the memory bank adds essentially no additional disadvantage on Explore. Both models struggle equally on novel destinations. The trainable time encoder — shared by both — is the primary cause.

The mechanism: a trainable encoder learns to assign high scores to recently-visited destinations. On Explore edges, every recency negative is a recent visit and the positive is a novel destination the encoder has never associated with this source. The encoder's bias inflates all the negative scores, collapsing Explore performance. GraphMixer's fixed encoder does not learn this bias, so novel destinations are not penalized.

GraphMixer beats TGN even on Return edges

This is unexpected. The memory bank was predicted to give TGN a clear advantage on Return edges — it has literally recorded prior visits to the destination. Instead, GraphMixer wins Return MRR (0.834 vs 0.821).

The likely explanation: on some Return edges, the true positive $(u, v)$ is not the most recent visit — $u$ may have visited $v$ a while ago, and more recent visits to other destinations rank higher under TGN's recency bias. GraphMixer, treating all neighbors uniformly, does not inflate those more-recent competitors.

The K-curve is flat for all models

All three models drop only 0.012–0.014 from K=10 to K=999. The predicted GraphMixer drop-off past K=20 did not materialize. This is itself an informative result: the depth of the recency negative list is not the key driver of performance differences. The model's architectural bias is already fully expressed at K=10. Adding more historically-recent negatives beyond the first 10 adds competitors that are scored similarly to the shallower ones.

The K-curve's value as a diagnostic is deferred to the federated learning experiments. If federation fragments TGN's memory bank, the federated curve should drop at larger K while the centralized curve stays flat — and the crossover K becomes a quantifiable measure of what federation costs in temporal memory.

7.1 Recency MRR versus memorization

EdgeBank establishes the memorization floor for both metrics. On Standard MRR, the floor is 0.495 — barely below every neural model. On Recency MRR, the floor is 0.362 — well below every neural model. The gap between neural models and EdgeBank is 4–8× wider on Recency MRR than on Standard MRR.

ModelAdvantage over EdgeBank (Standard)Advantage over EdgeBank (Recency)Ratio
TGN+0.106+0.4274.0×
TGAT+0.073+0.4115.6×
GraphMixer+0.054+0.4598.5×

GraphMixer shows the largest Recency advantage (8.5×) because its fixed encoder is not confused by the recency negatives, while its Standard MRR advantage is the smallest because its lack of temporal bias does not help with Standard's random negatives. TGN shows the smallest Recency advantage ratio (4×) because its trainable encoder inflates recency negative scores, cutting into its Recency MRR.

The EdgeBank Explore MRR (0.284) deserves special attention. On Explore edges, the positive destination has never been seen — so EdgeBank scores it 0.0 — while every recency negative has been seen — so EdgeBank scores them 1.0. The positive always loses. This is a hard floor: even neural models that genuinely generalize to novel edges are still well above this floor (TGN 0.708, GraphMixer 0.787), confirming those Explore gains represent real structural generalization, not memorization artifacts.
